# 原生 CLI 功能对齐方案（待实施）

## 核对范围和结论

2026-10-02，对照本机 agy v1.2.14、扩展 2.1.3 源码、既有真实协议样本。读取 agy --help、各管理子命令帮助、agy models、agy agents，并在独立临时目录打开原生 TUI 的 / 补全菜单。菜单候选包含别名和技能；本次摘录了 33 个不同名称，不将其声称为完整注册表。菜单可见不等于 Stream-JSON 可以执行。未运行功能回归测试或修改扩展实现。

结论：以斜杠命令作为统一入口，优先完成侧栏原生功能；TUI 专用或协议未支持的操作交接到 VS Code 集成终端。不能承诺当前 Stream-JSON 在侧栏实现全部 TUI 能力。完整覆盖入口与完全同一交互体验应分别验收。

## 命令系统

CommandRegistry → Parser → Dispatcher → Controller / NativeManagementAdapter / VerifiedSkillAdapter / NativeTerminalAdapter。

注册项记录来源、别名、参数模式、是否要求空闲、支持版本、是否为模型请求、是否修改配置、失败恢复方式。菜单显示：侧栏可用、原生终端、尚未验证。显示候选不代表能力已支持。

- 只有输入开头的 /命令触发，代码围栏及正文里的路径不触发；// 开头转义为普通文字。中文输入法组合期间 Enter 不提交，Shift+Enter 换行。
- 本地控制命令不进入模型历史，不产生模型调用或工具请求。命令记录与对话内容分开。
- 参数支持引号与含空格路径，使用 spawn 参数数组，不经 shell 拼接。
- 未知命令明确报错，不能当普通自然语言交给模型执行。
- 同名冲突显示来源。/plan 按扩展受限规划执行，不静默调用原生同名技能；预留显式 /skill <名称> 调用经验证的技能，不绕过 Plan 限制。
- /approve 显示将执行的方案绑定，忙闲状态、请求去重、旧回复隔离和 UI 按钮共用原有控制器。
- 模型、主 Agent、沙箱、目录、schema 的配置变化只在空闲时生效；仅需要的新启动参数触发重启，不影响其他后台会话。

## 原生交接修复

当前 openNativeCli 会先 abortTurn，交接参数缺少附加目录与独立 effort 传递；原生终端结束后也没有完整回流同步。这些需要先修复，不能把现有 CLI 按钮当成已完成的功能兜底。

- 忙时不静默停止或启动同 ID 的第二个进程。说明交接影响，等待任务结束或由用户明确停止后交接。
- 空闲时释放扩展持有的进程，再持有会话执行锁并以相同 native ID、cwd、额外目录、实际模型/effort、Agent、模式、权限、schema、sandbox 参数启动原生终端。
- Plan 原生交接仍保留只读 Agent 限制。用户主动切执行模式时才使用正常执行身份。
- 终端退出后解除本次锁；从原生记录按需同步可展示的新消息，保留原本地历史和稳定消息标识，验证恢复会话。
- 运行中的外部 CLI 不强占锁，不清理仍活跃的锁，不停止其他会话。外部工具子进程迁移是否支持单独验证。

## 分阶段实施

### P0：协议清单与交接可靠性

整理本机完整内置命令、别名、技能与管理子命令；逐个确认入口、输入/事件格式、版本范围。按需使用隔离目录验证 print/Stream-JSON 行为，改变配置或调用外部接口的功能需限定自己的测试资源。补齐原生交接参数、忙时行为与恢复；修正旧架构文档关于新建会停止旧轮次的过时描述。

### P1：统一 slash 和现有功能对齐

实现命令路由、补全、/help；新建/停止/历史/文件/Plan/明确批准/模型/effort/子代理入口。动态模型列表缓存；验证 max 与模型 suffix 规则，不伪装生效。保留小量常用按钮，其余能力从命令访问。

### P2：CLI 配置及可验证技能

实现主 Agent、技能、MCP/插件管理、附加目录、sandbox、schema、usage。所有项目路径继续以 VS Code 工作区为基准；不回退到独立绑定项目。不要读取、展示或复制 API 密钥到历史。

### P3：任务和 Artifact 数据

核对并实现 artifact/tasks/edited、逐轮 diff、可验证 browser/goal 等技能；只对可见详情订阅/读取，按需分页。/btw 若没有可靠输入协议仍保留原生入口。

### P4：依赖 CLI 协议或平台能力的部分

权限问答传输、子代理精确生命周期/token、旁问、配额、语音、持久调度、远程控制。通过真实原生能力和输入协议验收后再启用；否则保留功能完整的终端入口和准确的限制说明。不另造服务冒充原生语义。

## 性能约束

- 本地控制命令零模型请求；动态列表按需读取并缓存，失效由版本/文件变更/显式刷新触发，避免固定轮询和每键启动 CLI。
- 补全在本地索引处理；不新增常驻 CLI、每会话终端或后台模型请求。
- 保持约 30 ms 增量批量和完成后 Markdown 解析；隐藏会话仅送状态，详情分页并限制订阅。
- 用现有 100k 文本/1000 工具/80 MB/后台会话负载检查 P95≤100 ms，同时测量本地命令响应与首个模型事件分开。

## 验收与交付

每个已公开命令具有真实语义测试，包括参数、别名、中文组合输入、双击、忙时调用、失败恢复、重建、旧回复隔离。贯穿实际 Webview → Provider → Controller → 模拟 CLI；CLI 能力另用真实隔离样本确认，不能相互代替。

真实安装窗口完成 slash 新建→发送→Plan→批准→后台切换→技能/管理操作→CLI 交接→回流→重载→历史恢复。不能停止用户原任务作为验收步骤。

每阶段独立版本、VSIX/历史/配置备份与回退说明；记录当前CLI版本、完整对齐表、样本、性能和已知限制。已实现、终端可用、协议受限三种状态分别统计，不能宣称所有能力都已在侧栏复刻。
