## 一、结论与实施原则

目前已有分层、后台对话、受限 Plan、流式显示、子代理面板和命令入口。后续采用分阶段改造：先收紧执行与恢复语义，再处理渲染、磁盘和缓存，最后补齐功能。每阶段都有独立验收和可回退版本。

性能优先落实为以下约束：

- 保留原 `agy` 启动器、接口、模型、思考深度和用户权限选择；性能对照配置一致。
- 普通发送复用 CLI；本地命令与补全不产生模型请求。正常流不增加常驻发现进程、固定轮询或自动模型重试。
- 新建、切换、浏览历史不会停止其他对话。停止、批准和文件应用都针对明确的对象。
- 项目继续跟随 VS Code 工作区；已运行会话固定创建时的主目录。
- 原生协议没有的数据显示未知。已有拒绝不当作待审批，观察时间不当作准确运行时间。
- 重构按模块推进，保留现有记录兼容性。存储升级只有在旧格式确实不能支持时才引入。
- 真实安装窗口、协议样本、模拟链路和性能回放分别验收，互不替代。

## 四、执行与会话设计

### 4.1 不可变的轮次配置

引入 `ExecutionProfile`：cwd、全部操作目录、requested/effective model、effort、主 Agent、Plan 工具策略、权限、sandbox、schema 内容指纹、CLI 版本/路径。每轮开始固定一份，展示和参数都从它生成。

- 用户主动新建：继承模型、深度和权限；默认普通模式，清空附件，旧草稿仍归旧会话。
- 恢复目录不兼容：保留旧历史，在新项目建立会话；保持当前请求的模式和限制。旧项目附加目录不自动带到新项目。
- Plan 要求在发送前再次核对只读 Agent 与实际参数。配置不一致则保留草稿并失败，不自动改成普通模式。
- 批准使用 `sessionId + planMessageId + revision`，捕获确切方案和执行 Controller。任何新 Plan、重定向或重复提交都不能改变批准对象。
- 权限逐步改为明确的会话执行配置；全局设置作为新会话默认。迁移时采用当时已选配置并显示来源，不能推断旧历史实际权限。运行中的轮次不因其他对话更改默认值而变化。
- 配置未变化时不重启进程；管理操作完成后再标记需要加载的新 revision。

### 4.2 控制器与选择分离

- Coordinator 负责选中对象、创建/删除/交接事务和资源预算。
- Controller 负责一个会话的执行，UI 切换只改变订阅。
- 新建/切换/删除/交接的选择更新统一排序；按请求起始时捕获目标，不能在 await 后再把“当前会话”当目标。
- Stop 为优先通道，可取消启动和写入。UI 先显示停止已受理，再显示进程清理/记录保存结果。
- stdin 或协议错误导致执行结果不确定时，结束该进程代次并记录未知状态；不直接复用可能仍在处理旧轮次的进程。
- 没有原生 turn ID 的协议不能仅靠本地 turn ID 保证同进程迟到事件隔离。按已验证边界处理，异常时保守重建进程。
- 新任务资源预算只约束新启动；已有任务不自动停止。保留最多两个已确认可释放的空闲 CLI，另统计状态未知的执行器及其内存。

### 4.3 拆分范围

逐步抽出 `TurnRunner`、`PlanPolicy`、`ExecutionProfileResolver`、`NativeHandoff`；Provider 抽出命令 Dispatcher、Editor Actions、Context Adapter。Webview 抽出 Composer、MessageList、ToolDetails、AgentPanel 和 RequestClient。

共享命令注册表同时描述参数 schema、是否需空闲、是否产生模型请求、是否改配置、路由和能力条件。`/help`、补全、按钮和执行校验从同一描述生成。第一轮不替换 CLI 或 React，也不另造模型/子代理引擎。

## 五、性能优化设计

### 5.1 渲染与传输

1. **正文与工具批量更新**：继续约 30 ms 合并文字；工具状态同样批量，最终状态保证发出。停止和错误走优先通道。
2. **按 ID 订阅**：消息、文本块和工具使用索引；Composer 不因每个正文增量重渲染全部聊天。检查重复保存 content/blocks 的内存成本。
3. **记录块完成**：消费 stepDone，已结束块可以分步渲染；未闭合围栏保持纯文本。避免每次 token 增量扫描完整回答。
4. **长内容解析**：先提供可读文本；Markdown 按块调度和缓存。确有收益才把 tokenize 放到 Worker，DOMPurify 与 DOM 应用保持正确边界；大 DOM 更新也要分步，Worker 不能解决全部渲染成本。
5. **虚拟化**：消息和工具列表按视口挂载，保留合理 overscan；动态高度、文本选择、代码复制、键盘导航和分页滚动锚点同时验收。
6. **隐藏侧栏**：执行层继续保存记录，只传必要状态；重新显示从快照及序列恢复，避免为每个隐藏增量发送 IPC。
7. **大工具原文**：按 CLI 已验证的增量/全量语义保存，不盲目 append。原文尽早写到独立文件，内存只保留预览和有限读取窗口。
8. **资源上限**：IPC 单批大小、待写字节、解析时长、缓存字节和订阅数都有预算；超过预算优先分页/延后显示，不能静默丢掉真实回答。

### 5.2 存储与恢复

- 启动先异步读取元数据，当前会话消息优先；历史文件异步按需分页。首次迁移可恢复，并明确进度。
- 每会话一个合并写入队列；保存 dirty 消息/工具/元数据 revision。草稿保存不再遍历并序列化全部已加载历史。
- 完成/停止建立明确提交点；只有保存成功才更新 committed revision。失败保留 dirty 数据并允许重试，区分“执行完成”与“记录尚未保存”。
- 在现有 v3 格式上增加提交标识或恢复 manifest；评估必要性后再决定日志重整，避免立即引入数据库迁移。
- 运行中 checkpoint 的恢复窗口目标不超过 1 秒；磁盘失败必须显示例外。原子 rename 不等同突然断电可恢复，实际持久化保证需说明。
- 历史页缓存按字节和数量淘汰；选中/活动轮次 pin，其余释放。删会话清理全部缓存，删除失败可以恢复目录或重试，不让 UI 永久误报已删除。
- 跨窗口打开同一历史时刷新已变更 revision；执行锁与写入锁职责清楚。PID 锁需考虑 PID 重用、终端跨重载和锁属主失效；不能清理仍活跃属主。
- events.ndjson 与临时文件建立恢复、压缩和保留规则；不自动删除用户历史。

### 5.3 JSONL 与子代理

- 父/子日志复用完整记录读取器：UTF-8、最后未完成行、超长行、文件截断/替换都可处理。只有完整记录被解析或明确拒绝后才提交游标。
- 64 KiB 是显示页大小，不作为单条 JSON 的硬截断位置。大记录有有界解析策略及独立内容页；超出支持范围明确提供原日志入口。
- 共用公开投影白名单；未知 record.type 保留原始记录但不自动展示。子任务输入、工具结果先用真实样本定义可见语义。
- 面板打开才订阅。选中子代理对话按新偏移读取；状态变化只刷新对应卡片。关闭、隐藏、重建清理 timer/watchers，重新打开立即可用。
- 总数、最近运行/结束状态与当前轮次分开，历史子代理不会冒充本轮启动。观察时间明确标注，精确 token 与生命周期在原生提供之前保持不可用。
- 深层子代理发现仅在面板打开、日志提供可信 ID 和关系时按需递归；需要新样本验证，设置深度/数量上限，不扫描整个 brain 目录。

## 六、交互与原生功能补齐

### 6.1 输入与错误恢复

- RequestClient 按操作类型设置超时/取消；新 Webview 实例主动同步。超时描述“结果未确认”，不把执行中操作当成失败重发。
- Bridge 缓存完成/失败结果，有界重放；pending 操作不能因普通 LRU 淘汰而重复执行。序列缺口只允许一个快照同步请求在途。
- 草稿/附件写入携带 sessionId 和 draft revision；过时 debounce 不覆盖新输入。普通文字和安全命令草稿都可在侧栏重建恢复；凭据管理命令不持久化。
- 补全支持上下键、Tab、Escape，与 IME 组合输入兼容。不会因选补全而自动发模型请求。
- 文件链接和代码按钮的错误在所属消息显示，不用空 catch 隐藏失败。
- 尊重 autoScroll；在消息锚点上恢复滚动，不因切换完成快照把已加载历史和位置丢掉。
- 区分连接、无新输出、工具运行、已自动拒绝、停止清理、保存失败。等待期间显示已耗时和实际状态，不猜模型在做什么。

### 6.2 文件与上下文

- 附件保存真实 URI、范围、版本及内容摘要，显示文本与路径分离；支持多个文件和选区。
- 大文件先显示字节数与范围，用户可选片段；预算按真实字节统计，不把未经校准的估计声称为准确 token。报错上下文按项目与数量控制。
- 文件跳转、命令路径、附加目录和 diff 使用统一路径解析：WSL/Windows、空格、Unicode、百分号、URI 和行列号。
- 预览使用唯一 previewId 和目标 URI，清楚显示是替换文件还是选区；同名不同目录、多代码块与跨会话不会共享预览。
- 应用前核对 URI、内容/版本和预览归属；文件变化后要求重新预览。预览关闭后释放 DiffProvider 内容。
- `/diff` 保留 Git HEAD 语义；新增 `/diff turn` 需要可信轮次变更记录或对已验证修改路径的前后快照。其他会话/外部编辑混入时明确标注，不能声称所有变化由本轮产生。
- `/edited` 增加明确范围，区分工作树改动和本轮观察到的修改文件。没有可靠操作记录时继续使用工作树视图。

### 6.3 CLI 能力与交接

- 每个 CLI 路径/版本建立缓存能力表，解析未知版本时限制未经确认的功能；能力发现只用管理/帮助输出，不隐含模型请求。
- requested/effective model 与 effort 同时可查；模型族规则由经验证能力描述驱动，UI、设置与交接保持一致。
- 技能显示来源和名称冲突，缓存有界且可刷新。配置变更在管理命令完成后失效；插件安装打开终端不当作安装成功。
- 交接状态明确为侧栏持有、转移中、终端持有、待同步、可恢复。共用启动参数和 cwd 校验，持有正确原生会话执行锁。
- 真实终端新增消息有稳定 ID、文件身份与游标，重复同步不重复导入。日志替换/截断不静默覆盖已有历史。
- 首先完成“侧栏 → 同 ID 原生终端发送 → 关闭 → 回流 → 侧栏续聊”的真实窗口验收。
- 跨宿主重载外部终端接管作为独立研究项。未验证前清楚说明不能接管，不能自动解除活跃锁。

### 6.4 受协议限制的功能

| 功能 | 开放条件 | 目前处理 |
| --- | --- | --- |
| 主界面批准每个主/子代理操作 | 真正 pending 的 request ID、可回复协议、拒绝与超时语义，以及实际执行前拦截证据 | 保留原生终端；不从 denied_actions 造审批队列，不靠事后停止保证审批 |
| 精确 Agent 状态/时长/token | 原生生命周期与独立用量字段或等价可靠查询 | 保留最近观察/未知标识 |
| `/btw` | 有独立输入类型、并行上下文与结果路由 | 原生入口；不向忙进程直接写普通 user 消息 |
| 原生任务/Artifact 评审 | 可信对象 ID、状态和操作协议 | 文件浏览可增强，完整评审继续原生 |
| goal/持久调度 | 原生持久化与关闭窗口后的执行语义可验证 | 原生入口，不把单条提示等同计划任务 |
| 配额/费用 | 原生配额接口与明确计费数据 | token 与额度分开；没有价格就不估算费用 |
| browser/语音/远程控制 | CLI 与 WSL 平台权限/服务链路验证 | 按需原生入口，不加入默认常驻服务 |
| Schema / sandbox | 分别验证输出合规和实际限制边界 | 实验状态保留；不自动重试修 JSON，不把启动成功等同隔离通过 |

若用户最终需要在关窗/重载后继续执行，可另立可选本机执行服务方案。这会增加常驻进程、锁接管和升级复杂度，本轮不作为默认性能改造。

## 七、诊断与性能验收

### 7.1 可解释的时间线

使用 request/turn/session/generation 标识串起：点击 → 命令受理 → CLI 启动/init → stdin 完成 → 首个文字事件 → Webview 收到 → 对应正文 DOM 更新 → 下一帧可见 → 最终内容解析 → 保存提交。

可选 `/diagnostics` 展示扩展/CLI 版本、有效配置、进程数、队列大小、缓存字节与上述时长；导出默认只含结构化诊断，排除密钥、环境变量、正文与工具原文。stderr 保留限长脱敏尾部，给出错误类别，不能只剩字节长度。

默认不开启持续高频测量。使用单调时钟；跨 Windows/WSL/Webview 时校准时钟或报告分段耗时。采样要对应真实正文，不能把任意 DOM 变化当文字已显示。

### 7.2 发布门槛与目标

| 指标 | 计划门槛/目标 | 测量条件 |
| --- | --- | --- |
| CLI 文字事件到可见正文 | **P95 ≤100 ms** | 同机、确定性实际 bundle 完整链路；每场景 ≥1000 有效增量，至少 3 次 |
| 输入到草稿显示 | 目标 P95 ≤50 ms | 大回答、持续工具流、后台对话时；真实输入/DOM 采样 |
| 点击停止到受理状态 | 目标 P95 ≤100 ms | 启动中、正文中、工具流中与完成解析期间 |
| 停止到自有进程组退出 | WSL 目标 P95 ≤1 s | 另核对 CLI 与自有工具后代，不仅等按钮恢复 |
| 已缓存本地命令 | 目标 P95 ≤100 ms | `/help` 等零 CLI/模型命令；管理查询另计 |
| 新建/暖切换 | 目标 P95 ≤200 ms | 执行未阻塞、存储正常；冷恢复单独报告 |
| 完成长回答 | 热交互期间扩展产生的长任务目标不超过 100 ms | Markdown、路径识别、工具列表同时测；大内容分步可见 |
| 恢复与内存 | 缓存有上限，反复访问不会持续线性增长 | 100 次会话/面板切换与清空缓存后比较；分别报告 Host/Webview/CLI |
| 闲置与隐藏 | 无固定发现轮询，无逐 token 隐藏正文 IPC | 60 s 闲置/隐藏观察，报告相对基线 CPU、消息与订阅数 |
| 保存恢复 | 成功 checkpoint 的丢失窗口目标 ≤1 s | 运行中异常退出恢复；磁盘失败明确报告不满足 |

除原有 P95≤100 ms 外，其余为新增设计目标，先取得可靠基线。未达到需记录原因和改进，不把目标写成已达成。内存不先宣称固定 MB 保证，先按当前机器测量稳定值与增长趋势。

负载矩阵：普通短回答、10 万字/100 万字、长未闭合与闭合代码围栏、1000/10000 工具卡片、80 MB/更大输出、持续工具流、3/10 后台对话、20/100 Agent、超长 JSONL、1000/10000 历史会话、慢盘/磁盘满、隐藏侧栏、2 小时持续使用。高一级负载用于找上限，不能把它混为基础门槛已经通过。

### 7.3 原生对照

影响性能的阶段发布前，比较原生 TUI、直接 Stream-JSON、已安装侧栏：各 5 组冷启动、5 组续聊，增加文件读取/多工具场景。全部用相同接口、模型、effort、权限和提示。

分别报告启动、首个协议文字事件、扩展显示、总时长、成功率和原始样本；原生 TUI 没有精确模型 token 时间线时如实说明。不把全部首字等待归因扩展，不通过降低配置掩盖差异。

1. 持续回放固定场景、节奏、输入与事件大小，至少三次，每次至少 1000 个有效正文增量；超大场景的 21 样本探查仅作定位。

3. 分别采集 Extension Host、Webview 与 CLI/后代 CPU、RSS、堆、句柄/订阅、IPC 字节与磁盘队列；报告空闲/隐藏 60 秒和连续 2 小时的趋势。
4. 负载按基础与探查上限标注：10万/100万字、1千/1万工具、80 MB 与更大工具原文、3/10 后台对话、20/100 Agent、1千/1万历史、长代码与慢盘。输入、滚动、复制、停止均在负载期间测量。
